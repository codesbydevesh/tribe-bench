**Stated ambiguities:**

- BASELINE ESTIMATOR in (2) -- the central ambiguity. 'the average of the responses for the OTHER categories' admits two readings: macro (unweighted mean of per-category means, each category counts once) vs micro (pooled grand mean over all non-target events, each exemplar counts once). I chose MACRO, because the grammatical unit averaged is the category and it keeps the contrast invariant to unequal exemplar counts, matching the conventional localizer contrast vector faces > (objects+scenes+bodies)/3. The two agree iff all categories have equal n. If the two implementations disagree numerically, test this first: rerun with equal exemplar counts per category; if the disagreement vanishes, macro-vs-micro is the entire explanation.
- FAILURE BEHAVIOUR in (1) for a row that does not exist -- I raise IndexError naming every offending event and its arithmetic (onset + lag -> row). Alternatives not taken: clip to the last row, drop the offending events and return a shorter array, or NaN-fill. All three return a plausible-looking array and would silently corrupt the downstream contrast.
- Negative onsets are rejected even when onset+lag lands in range, because NumPy would silently wrap them to the end of the run. A permissive implementation would accept them.
- Duplicate ROI vertex indices raise ValueError (they would silently double-weight the mean). Alternatives: silently de-duplicate, or allow the implicit weighting. Most implementations do not check at all, so this is the check most likely to make mine error where the other does not.
- Empty verts or empty onsets_tr raise ValueError rather than returning a shape-(0,) array. The alternative (return empty) is defensible for zero events but feeds a NaN downstream.
- Non-finite values at the read positions raise ValueError instead of being handled by nanmean, in both (1) and (2). nanmean would compute each event's mean over a different, unstated vertex subset.
- Return dtype is float64 even though preds is float32 per source-of-truth.md. Expect ~1e-7 relative differences against a float32-preserving implementation; compare with a tolerance, never exact equality.
- lag_trs must be integral (5.0 accepted, 5.5 rejected). No interpolation between rows. Negative lags are permitted in principle (pre-onset baseline) but the resulting row is still range-checked.
- Integral-valued float arrays are accepted for verts and onsets_tr and coerced to int64; non-integral floats raise. A stricter implementation would reject all floats.

- A bilateral ROI's flat vertex mean is implicitly weighted by each hemisphere's vertex count (left 0..N-1, right N..2N-1). An alternative would average per hemisphere then average the two. Spec says mean over the ROI's vertices, so I did the flat mean.

### [CRITICAL] glm_contrast_z uses a pooled (equal-variance) SE; at unequal n its permutation test is not level-alpha in either direction

**Claim.** The standard error is Student's POOLED two-sample SE, which assumes the two conditions have equal across-observation variance. That assumption is harmless at equal n (permutation tests are famously robust there) but fails badly at unequal n. Because the resulting statistic is not asymptotically pivotal, wrapping it in a permutation test does NOT rescue it (Behrens-Fisher; cf. ### [MAJOR] detection_floor's absolute `tol` skips the bisection entirely for small-scale statistics and silently returns the raw doubling bracket

`/home/deveshb/workspace/AI/tribe-bench/tribe_tools/roi_stats.py` :: `detection_floor (line 392; the bisection is lines 445-461)`

**Claim.** The bracket is `lo, hi = 0.0, noise_sd` doubled until powered, so after bracketing hi - lo == hi/2 ~ noise_sd. The refinement loop is `while hi - lo > tol` with an ABSOLUTE default tol=1e-3. Whenever noise_sd is of order tol or smaller, the loop body never executes and the function returns the untouched doubling bracket — up to 2x the true MDE — with no warning that no bisection occurred. **Evidence.** Ran, n=15 per group, n_sim=60, n_perm=200, seed=0, default tol=1e-3:

  noise_sd=0.001  -> floor 0.00200   ratio 2.000   <-- zero bisection steps, 79% overstated
Mechanism confirmed: at noise_sd=1e-3 the bracket after doubling is [0.001, 0.002], width 0.001, and `0.001 > 1e-3` is False, so the loop is skipped and `hi` is returned verbatim. **Fix.** Make the tolerance relative to the scale: default `tol=None` -> `tol = 1e-2 * noise_sd`, or change the loop to `while (hi - lo) > tol * max(hi, 1e-30)`.
